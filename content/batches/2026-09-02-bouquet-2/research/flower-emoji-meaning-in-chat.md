## Phase 2 — Gap analysis

**Table stakes** (covered by all the dictionaries, so the post must carry them):
which flower emojis exist, their Unicode character names, their code points, the
fact that vendors render them differently.

**The gap.** The emoji dictionaries document what each glyph *is* — Unicode name,
code point, vendor artwork gallery — and almost nothing about what *sending* one does
between two people. But the modifiers driving the demand (`in chat`, `whatsapp`,
`love`, `instagram`, `what does the dead flower emoji mean`) are all asking the
relational question, not the lexicographic one. That is a question about mediated
communication, there is real research on it, and nobody on this SERP cites any.

**Stale/absent data.** The dictionaries carry no research at all. There is no
statistic on those pages to supersede — the deficit is categorical, not temporal.

**Unanswered questions the SERP raises and drops.** Why does the same emoji land
differently for two people? Why does a flower read differently in an Instagram
comment than in a WhatsApp thread? When is an emoji actively the wrong move?

  claims used (`combined N = 451`; positive replies signalled greatest interest

- **Source 3 — scope kept narrower than the claim.** Grosz, Kaiser & Pierini's two case

## Unicode and platform-rendering claims — what was and was not verified

`unicode.org` is a closed domain (6 prior posts) and so is `w3.org` (5), so no Unicode
fact in this post is sourced to a published page. Instead:

**Verified directly, locally, and stated in the post:**

- Code points and character names, read out of the Unicode Character Database via
  Python's `unicodedata` with `unidata_version == "16.0.0"`:
  U+1F337 TULIP, U+1F338 CHERRY BLOSSOM, U+1F339 ROSE, U+1F33A HIBISCUS,
  U+1F33B SUNFLOWER, U+1F33C BLOSSOM, U+1F3F5 ROSETTE, U+1F490 BOUQUET,
  U+1F4AE WHITE FLOWER, U+1F940 WILTED FLOWER, U+1FAB7 LOTUS, U+1FABB HYACINTH.
- **"Twelve characters … carry a flower as their character name"** is our own
  enumeration of that database (a full sweep of all 0x110000 code points for
  flower-name substrings, discarding non-emoji hits such as U+2055 FLOWER PUNCTUATION
  MARK and U+1F023 MAHJONG TILE ORCHID). It is phrased in the post as a count of
  characters whose *character name* is a flower, **not** as the size of Unicode's own
  `plant-flower` emoji subgroup, which could not be checked without `emoji-test.txt`.
- 🥀's correct Unicode character name is **WILTED FLOWER**, not "dead flower". The post
  uses the searched phrasing in the heading and gives the accurate name in the body.
- The artwork comes from a vendor-shipped font: `Apple Color Emoji.ttc` was confirmed
  present in `/System/Library/Fonts/` on the machine this was written on, and the UCD
  record for each character carries a name and a category and no image data.

**Could NOT verify, and therefore absent from the post:**

- **Which Unicode or Emoji release first carried any of these characters.** No version
  claim ("added in Unicode 9.0", "Emoji 15.0") appears anywhere in the article. The post
  says so in a closing note.
- **Unicode's own emoji grouping/subgroup structure** (`emoji-test.txt`,
  `emoji-sequences.txt`) — unreachable without `unicode.org`.
- **Any per-vendor rendering comparison as published fact.** That Apple, Google, Samsung
  and WhatsApp draw *different* roses is stated as a consequence of vendor-supplied
  fonts, which was verified locally; it is **not** attributed to a study, because the
  study that documents it (Miller et al. 2016) is spent. The post never states how any
  specific vendor's rose looks.
- The SERP itself was not re-measured (`WebSearch` exhausted).
